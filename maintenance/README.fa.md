# نگهداری و به‌روزرسانی دارفانت

دارفانت از دو منبع اصلی استفاده می‌کند: [v2rayN](https://github.com/2dust/v2rayN) برای برنامه و [Xray-core](https://github.com/XTLS/Xray-core) برای هستهٔ اتصال. کد Xray داخل این مخزن کپی نشده است؛ نسخهٔ رسمی ویندوز آن هنگام بسته‌بندی استفاده می‌شود.

## راه آسان از داخل گیت‌هاب

در صفحهٔ [Prepare upstream update](https://github.com/topgsmir/Darfant/actions/workflows/darfant-update.yml)، روی **Run workflow** بزنید و یکی از این گزینه‌ها را انتخاب کنید:

| گزینه | کاربرد |
| --- | --- |
| `Check` | نمایش نسخهٔ فعلی و آخرین انتشار رسمی؛ تغییری ایجاد نمی‌کند. |
| `Xray` | به‌روزرسانی مستقل هسته، بدون تعویض سورس رابط برنامه. |
| `V2rayN` | ادغام سورس نسخهٔ جدید با تغییرات دارفانت. |
| `Bundle` | به‌روزرسانی بستهٔ همراه ویندوز شامل sing-box، mihomo و داده‌های آن. |

در فیلد version می‌توانید `latest` یا برچسب دقیق انتشار را بنویسید. عملیات به‌روزرسانی، یک شاخهٔ جدا می‌سازد؛ پس از آزمون، ساخت برنامه و بسته‌بندی موفق، شاخه را می‌فرستد و یک درخواست ادغام پیش‌نویس می‌سازد. اگر تنظیمات مخزن اجازهٔ ساخت درخواست ادغام توسط Actions را ندهد، شاخهٔ آماده در بخش Branches موجود است و می‌توانید برایش Pull request بسازید.

برای به‌روزرسانی **سورس v2rayN**، هنگام پذیرش درخواست از **Create a merge commit / Merge pull request** استفاده کنید تا تاریخچهٔ مشترک حفظ شود. Squash یا Rebase، ارتباط ثبت‌شده با سورس اصلی را از این مسیر حذف می‌کند. برای تغییرات نسخهٔ هسته، Squash هم قابل استفاده است.

تداخل واقعی میان کد جدید و تغییرات دارفانت به حل دستی نیاز دارد. در این وضعیت، عملیات گیت‌هاب متوقف می‌شود و گزارش `upstream-conflicts` را در همان اجرا می‌گذارد. با روش محلی زیر ادغام را انجام دهید. انتشار عمومی برنامه عملیات جداگانهٔ **Build Darfant for Windows** است و روی یک انتشار پیش‌نویس انجام می‌شود؛ فایل نصب EXE و نسخهٔ قابل حمل ZIP، هر دو به آن پیوست می‌شوند.

## محل تنظیم نسخه‌ها و تغییرات اختصاصی

| محل | مسئولیت |
| --- | --- |
| `maintenance/dependencies.json` | برچسب و شناسهٔ دقیق سورس مبنا، نسخهٔ بستهٔ همراه و Xray، و SHA-256 فایل‌ها. |
| `Darfant/Branding.props` | نسخه، نام و آیکون برنامه. شمارهٔ نسخهٔ دارفانت را فقط اینجا تغییر دهید. |
| `Darfant/app.manifest` | اجرای همیشگی با دسترسی مدیر ویندوز. |
| `Darfant/Windows.targets` | اتصال مشخصات و منابع دارفانت به ساخت با یک خط Import در پروژهٔ اصلی. |
| `global.json` | نسخهٔ SDK ساخت؛ فرایندهای گیت‌هاب هم نسخه را از همین فایل می‌خوانند. |
| `installer/Darfant.iss` و `installer/toolchain.json` | قالب نصب فارسی و نسخهٔ ابزار ساخت نصاب؛ شمارهٔ برنامه از Branding خوانده می‌شود. |
| `v2rayN/v2rayN/Views/MainWindow.Darfant.cs` و `MainWindow.Servers.cs` | فرمان‌های رابط اختصاصی و دسته‌های سرورها. |
| `v2rayN/v2rayN/Resources/DarfantTheme.xaml` و `Resources/Flags` | ظاهر ظریف برنامه و تصاویر پرچم‌ها. |
| `v2rayN/ServiceLib/Common/ServerLabels.cs` | تشخیص کشور و اپراتور از نام کانفیگ یا اشتراک. |
| `maintenance/Test-Darfant.ps1` | بررسی ساخت، نام و نسخه، تاریخچهٔ مبنا و آزمون‌های اختصاصی. |

فایل پروژهٔ WPF تنها یک خط Import اختصاصی دارد؛ مانیفست اصلی و نسخهٔ مشترک v2rayN برای دریافت تغییرات بالادستی نگه داشته شده‌اند. مانیفست و مشخصات دارفانت جدا اعمال می‌شوند. بخش‌هایی که لازم است با کد اصلی یکپارچه باشند، هنوز تغییرات کوچکی در فایل‌های اصلی دارند. [نقشهٔ این تغییرات](CUSTOMIZATIONS.md) برای حل تداخل‌ها موجود است.

## به‌روزرسانی محلی

پیش‌نیازها: ویندوز ۶۴ بیتی، Git، .NET SDK 10.0.404 و PowerShell. دستورها را از ریشهٔ مخزن اجرا کنید. ابتدا تغییرات فعلی خود را ثبت کنید؛ ابزار به فایل‌های ثبت‌نشده دست نمی‌زند.

نمایش نسخه‌های موجود:

```powershell
.\maintenance\Update-Darfant.ps1 -Component Check
```

به‌روزرسانی مستقل Xray:

```powershell
.\maintenance\Update-Darfant.ps1 -Component Xray -Version latest
.\maintenance\Test-Darfant.ps1
.\Build-Darfant.ps1 -Output C:\Builds\Darfant-new
git commit -m "Update Xray"
```

به‌روزرسانی سورس v2rayN:

```powershell
.\maintenance\Update-Darfant.ps1 -Component V2rayN -Version latest
.\maintenance\Test-Darfant.ps1
.\Build-Darfant.ps1 -Output C:\Builds\Darfant-new
git commit -m "Merge upstream v2rayN"
```

اگر تداخل گزارش شد، فایل‌های مشخص‌شده را ویرایش و با `git add` ثبت موقت کنید؛ سپس:

```powershell
.\maintenance\Update-Darfant.ps1 -Component V2rayN -Continue
.\maintenance\Test-Darfant.ps1
.\Build-Darfant.ps1 -Output C:\Builds\Darfant-new
git commit -m "Merge upstream v2rayN"
```

برای لغو ادغام در حال انجام:

```powershell
.\maintenance\Update-Darfant.ps1 -Component V2rayN -Abort
```

شاخهٔ به‌روزرسانی پس از لغو باقی می‌ماند. برای ادامهٔ کار معمول می‌توانید `git switch main` بزنید.

بستهٔ همراه را جدا به‌روز کنید؛ این انتخاب با دریافت سورس جدید عوض نمی‌شود:

```powershell
.\maintenance\Update-Darfant.ps1 -Component Bundle -Version latest
.\maintenance\Test-Darfant.ps1
.\Build-Darfant.ps1 -Output C:\Builds\Darfant-new
git commit -m "Update Windows core bundle"
```

وقتی Xray به انتشار مستقل تغییر کرد، به‌روزرسانی Bundle آن را بازنویسی نمی‌کند. در حالت اولیهٔ `source: bundle`، نسخه و اثرانگشت Xray از همان بسته ثبت می‌شود.

## ساخت قابل تکرار و بررسی سازگاری

ساخت برنامه از نسخه‌های ثبت‌شده استفاده می‌کند؛ `latest` فقط هنگام درخواست به‌روزرسانی خوانده می‌شود. فایل‌ها از انتشار رسمی گرفته می‌شوند و پیش از استخراج، SHA-256 بررسی می‌شود. نسخه و اثرانگشت خود `xray.exe` هم کنترل می‌شود. دریافت‌ها در `.darfant-cache` نگه داشته می‌شوند و فایل `Darfant-dependencies.json` داخل خروجی، منابع دقیق هر بسته را ثبت می‌کند.

اگر بستهٔ اصلی کنار پوشهٔ مخزن باشد و اثرانگشتش با نسخهٔ ثبت‌شده بخواند، از همان استفاده می‌شود؛ در غیر این صورت دریافت خودکار انجام می‌شود. برای ساخت آفلاین، `-Bundle` و در حالت Xray مستقل، `-XrayArchive` را به فایل‌های ZIP متناظر بدهید. `-Dotnet` نیز مسیر SDK دلخواه را می‌پذیرد. پوشهٔ خروجی باید جدید باشد.

آزمون‌ها ادغام بدون تداخل، حفظ راهنما و فرایند ساخت دارفانت، رد تغییرات ثبت‌نشده، حل و لغو تداخل، رد فایل خراب، ساخت WPF، نام و نسخهٔ برنامه و تشخیص اپراتورها و دسته‌بندی تست پینگ را بررسی می‌کنند. پیش از انتشار هر ارتقای بالادستی، اتصال واقعی، TUN، عبور مستقیم ایران، محدودهٔ برنامه‌ها، ورود اشتراک و نمایش پرچم‌ها را هم روی ویندوز بررسی کنید؛ موفقیت ساخت به‌تنهایی سازگاری همهٔ تغییرات آینده را تضمین نمی‌کند.

## تاریخچهٔ مبنا

سورس اولیه از v2rayN 7.25.6 با شناسهٔ `1883178b5f1e222b6c6db2782e7a3d989b7cc18f` آمده است. یک ادغام فقط برای ثبت این مبنا، بدون تغییر محتویات دارفانت، در تاریخچه قرار گرفته است. بنابراین Git برای دریافت نسخه‌های بعدی، مبنای مشترک واقعی دارد. نسخه‌های آینده با ادغام عادی و سه‌طرفه دریافت می‌شوند؛ برای آن‌ها از `merge -s ours` استفاده نکنید، چون تغییرات نسخهٔ جدید را کنار می‌گذارد.
